CASE

这是全程最值得看的一段：三方都用 grep 查同一件事，三方都被同一行注释骗了。

谁说了什么对不对

三个人都 grep 了，三个都被同一行骗了。只有打开看原文才水落石出。

MANUAL

人工项的数字，不能当证据用

规范写明：人工项「只准备证据、标出可疑处，不下结论」。这次暴露出一个隐患。

QA 人工项报的主会话实测（CDP 1440×1024）差异
C 区一屏只露 4 行完整露出 7 行（共 15 行）低报
B 区条目中间空 550px最大横向空白 335px高报
B 区占 273px273px准

为什么这件事要写进来

owner 是基于「一屏只露 4 行」做的签字判断。那个数是 QA 看截图估的，不是量的。

偏差方向对结论有利（7 行比 4 行宽裕，取舍代价更轻），所以不用重签 —— 但如果偏差反过来，就会是基于错数做的决策。

沉淀：人工项里出现的数字，引用前必须机器复核一次。 否则一个估出来的数会被当成实测值，写进后续所有文档。

GATE

撞出一个流程冲突 · 而它没有绕行

常驻测试岗写不了验收报告

测试会话跑完全部检查，落报告时被门卫拦住：

enforce-skeleton 查 transcript 要求「本会话真派过 qa-agent」
→ 常驻测试岗本体写报告，在门卫眼里 = 自己出题自己判卷

根因：门卫是为「单主对话派 agent」那套跑法写的 —— 主对话不能自己写验收报告，必须派人。 但多会话架构里，测试岗本身就是那个独立第三方，它跟被验对象是两个会话、两份上下文， 根本不存在「自己判自己」。门卫的判据跟它想防的东西脱钩了。

它的处理：不绕行，走门卫指定的正路

测试会话没有申请豁免、没有绕过，而是自己派了一个 qa-agent 按契约跑一遍， 再拿这份跟它自己已跑完的结果对账，差异写进回执。

这比直接豁免有价值 —— 对账本身就是一次交叉验证。

要不要改门卫政策，是 owner 和流程岗的事。执行的人不动规则。

这一版真正的成本：4 轮返工，6 个机器查不出来的问题

机器项全过，不代表一次做对。下面每一条都是人工审出来的，九项通用标准一条都没抓到。

轮问题
1① 页面样式覆盖掉了组件自带的白底　② 100 个组件里 97 个用了 sm/xs 小号变体
2③ 第一轮改错了 —— 量到行背景是 rgba(0,0,0,0) 就断言「是白的」。 透明不是白，透明是显示背后那层。穿透到第一个非透明祖先才发现真正的灰底在容器上

4⑥ navbar 的 slot-header 本来支持两行（标题 + 描述），从骨架阶段起就只用了一行

这 6 个问题指向同一个结论：验收标准有洞

产物「合规通过」了 —— 九项通用标准一项没违。但人工一眼就看出不对。

两方从相反方向撞到同一个结论：测试会话从「今天抓到的问题，标准里都没有对应判据」， 主会话从「四轮返工的根子全在骨架阶段就埋下了」。

结果是三条新标准转正：R13 尺寸变体位置 / R14 组件默认不覆盖 / R15 对齐间距机器量， 外加两条「怎么量才不骗自己」的注记 —— 量背景色要穿透到第一个非透明祖先、 图标判空用码点不用 content 串。下一单起生效，不回填存量。

骨架阶段那条预判，兑现了

骨架阶段提前记了一条：var(--radius-md, 6px) 里的 --radius-md 在整个 设计系统的 CSS 里 0 处定义，一直吃的是 fallback。当时 R5 还不判，但先记下来了。

现在核对：高保真页里 --radius-md 出现 0 处，改用了梯度里真实存在的 --radius-sm（同为 6px）。没有新建 token —— 设计系统扩展的第一条硬约束就是「token 层零破例」。

提前一个阶段记下来的东西，到了那个阶段真的被用上了。这是「预判」和「事后补救」的差别。

一次「下游推翻上游」，而且下游是对的

最后一轮要把 5 个假数据人名换掉。派单里我写死了一句：「diff 里只应该出现名字。」

执行的会话没照字面做 —— 它同时改了 10 处头像首字，然后报备： 「只换全名的话，『岑亦舒』的头像上还写着『李』 —— 姓与首字不一致本身就是穿帮点， PII 检查也许不抓，人眼会抓。如果你坚持字面只换名字，回滚也是一条命令的事，但我的判断是不回滚。」

它是对的，我的指令有洞。我给的是一条字面规则，它执行的是规则背后的目的。

它的防误伤处理更值得看：周/孙/李 三姓在本页只属于要换的三人 → 全局换安全； 王/张 两姓有要保留的同姓者（王磊、张伟）→ 只在同一行里出现目标全名时才换首字。 一刀切的话，王磊的头像会变成「邱」。

验收方自己做的一件没人要求的事

换名这一轮要验「diff 里只有名字」。但这个目录不在 git 里 —— 没有基线，就没法 diff。

测试会话在改动落盘之前，自己抢存了一份旧版快照。派单里没有这一条。

后来它报的「新名分布与换名前基数严格一致（我落盘前数好的，不是拿新文件自证）」， 是同一个自觉的延伸 —— 拿改完的文件去证明自己改对了，等于没证。

PHASE 3

交互阶段 · 无死按钮

真组件页上做高保真交互。核心一条：每个按钮都要有反应，一个都不许留死。

查什么判据
无死按钮枚举全页控件逐个点，每个都要有真行为：页内交互 / 跳转 / 明确 disabled / 桩 + 说明去向
展开折叠必动画禁 display 硬切，用 grid-rows 0fr→1fr 自适应 + 淡入
级联扇出点开的二级页若还没建，接 coming-soon 桩并登记，报回主对话另起单元，不闷头造
行为自证真点 + 截图 + console 0 error，贴真实输出而不是「都通过了」

这一阶段有个已知的验收陷阱，先记着

无头浏览器会把 CSS 过渡冻在第 0 帧 —— 点完立刻量，会把「有动画」读成「没反应」， 等多久都不变。骨架阶段验 toast 时已经踩过一次。

正解：量之前先注入 transition:none，或者验 class 变化而不是验最终样式值。
