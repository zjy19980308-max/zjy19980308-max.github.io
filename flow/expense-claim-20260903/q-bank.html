STEP 0

选题过程也算记录

在问第一个问题之前，先花了一轮把「演示单元做哪个」定下来 —— 这轮的取舍本身就是内容。

owner 最初想用「会议中 · 空态」，我提了两条保留意见

① 一个空态，四道框架题空掉三道。页数=1 没有减法可做、导航不变、承载不变。 参照案例 11 个子题，我们大概只能问出 3~4 题 —— 而 Q-Bank 恰恰是最显功力的那页。

② 「对着成品反推」展示出来会露怯。参照案例是真从一份 PDF 需求出发的； 我们倒推的话，「推导」栏容易像马后炮。

owner 采纳，换成从 0 走的新单元。

我主动排除了候选里的「工位预定」

它跟参照案例的「会议室预订」几乎同构 —— 都是资源 + 时间段 + 预订， 页数决策和导航决策会长得一模一样，放一起看像照抄。

报销是「单据 + 流程」，完全不同构。owner 最终选：报销申请。

BANK Q1

角色 + 高频场景

决定 · 默认落地页 / 首屏重心 / 要不要角色变体区块

Q1.1 员工端要覆盖哪些角色SINGLE
A
仅申请人
只做「我交单、我看进度」，审批归管理端。最干净、页数最少，但少一道真决策
B
申请人 + 审批人
同一套页面，有审批权时多一个「待我审批」入口
C
申请人 + 审批人 + 财务复核
决策最多，但财务看的东西（批量核票 / 打款）跟员工差太远，会撑得太大

真实世界就是这样 —— 主管自己也要报销。 由此产生一道真决策留给 Q2：两个入口是并列成两页，还是同页 view 切换（= 页数减法）。

Q1.2 最高频的 2~3 个场景MULTI
✓
查进度 / 催办
交上去之后反复回来看「审到哪了、钱什么时候到」
✓
日常零星报销
打车、餐费，几张票就交一单
✓
出差整批报销
一趟差 20+ 张票，要归集成一单
✓
被打回来补材料
审批人退回，要改单 / 补票重交

默认落地 = 我的报销（读为主·频次最高）· 首屏顶部必须有 「需我处理」区 · 新建入口极轻，一个按钮直接开 · 一单多票的批量能力是硬需求 · 有审批权时多一个「待我审批」

一个不粉饰的偏差：题目问「最高频 2~3 个」，owner 四个全选

我没有替他删。而是把它变成一条设计约束：首屏必须同时扛「读进度」和「写新单」两件事， 不能只优化一头。这条约束直接生出了后面 Q3.2 的「置顶区 + 没事时自动消失」。

BANK Q2

合页 / 主+衍生

决定 · 页数减法

Q2.1 「我的报销」和「待我审批」怎么组织SINGLE
A
同一页 · 顶部 view 切换
两个页签「我提的 / 待我审批」
B
两个独立页 · 导航并列
职责最清楚、审批页能做批量操作，但页数 +1，无审批权的人 sidebar 会缺一块
C
待我审批归到首屏「需我处理」区
页数最少，但审批量大时首屏装不下

两者数据结构几乎一样（都是报销单列表，差别只在操作列），合页成立。页数 −1。 无审批权时把那个页签隐掉，不留孤禁标签。

Q2.2 一单多票（出差 20+ 张）怎么组织本单最硬的题
A
先传票再成单
票批量丢进「我的票夹」，OCR 跑完再勾几张组成一单
B
单内传票
先建单，在单里上传发票行。页数最少最直白，但出差回来要一口气传 20 张，且票没传完前单是半成品
C
两条都留
最灵活，但两套入口要想清楚怎么不重叠

A 贴真实行为 —— 票是零散攻入的，单是月底才拼的。 代价诚实说：页数 +1（多一个票夹），且票夹与单的关系必须在 Q3/Q4 讲清楚。

页数小结（Q2 之后）

−1（审批合页）+1（票夹）= 净持平，但结构完全变了： 从「单据为中心」变成「票 → 单 两段式」。

BANK Q3

导航 + 落地

决定 · 页面骨架

Q3.1 票夹放哪 · sidebar 几个入口SINGLE
A
两个入口，默认落地 = 我的报销
票夹是一级公民，平时随手丢票不必先建单
B
一个入口，票夹藏在新建流程里
导航最干净，但「随手先传一张票」这个高频动作没了入口 —— 跟 Q2.2 选 A 的初衷自相矛盾
C
两个入口，默认落地 = 票夹
因为「先传票」是流程起点。但跟 Q1.2 矛盾：查进度才是频次最高的

两条推导在这里第一次互相制衡：Q2.2 说流程从票开始，Q1.2 说频次从查开始。 结果是 —— 票夹给入口，但不给默认落地。

Q3.2 「需我处理」怎么让人第一眼看到SINGLE
A
首屏置顶区
列表上方一条，没事时自动消失不占地
B
状态筛选 + 计数徽标
更克制、结构更简单，但得主动点才看得到
C
顶栏铃铛通知
最轻，但通知容易被忽略，跟「四个场景全选」的信号不匹配

这个区同时装两种东西 —— 我被打回的单 + 待我审的单， 正好把 Q1.1（双角色）和 Q1.2（被打回补材料）两条推导收在一处。 没事时整块消失是关键：否则日常零星报销的人天天看见一个空盒子。

BANK Q4

表单 / 详情 / 轻量功能 承载

决定 · 哪些是独立页面，页数最终定下来

Q4.1 新建 / 编辑报销单用什么承载SINGLE
A
右侧抽屉
叠在列表 / 票夹之上，从票夹勾了票点「组成一单」时，能看见后面勾了哪几张
B
独立页面
20+ 张票横向铺表格更舒服、能批量编辑，但页数 +1 且从票夹跳过去丢上下文
C
居中弹窗
字段太多装不下，会变成弹窗内滚动

跟 Q2.2 的两段式天然契合 —— 抽屉的价值恰恰是「背景还在」。

Q4.2 报销单详情用什么承载SINGLE
A
独立页
内容多（发票明细 + 审批时间线 + 附件）、动作多（撤回 / 编辑 / 重交 / 催办）、要能发链接给审批人
B
右侧抽屉（跟表单一致）
形式统一、页数最少，但时间线 + 20 行发票在抽屉里很挤，且没法发链接

跟参照案例同一判断 —— 动作多 + 内容多 + 要分享链接 = 独立页。

Q4.3 OCR 识别完的票，怎么让人确认对不对很少人想的题
A
只标可疑项，不拦人
跑完直接入票夹，置信度低的字段标黄底；只在「组成单」那一刻才强制把黄底项清干净
B
传完逐张确认
数据最准，但出差回来传 20 张要确认 20 次，直接向后需求
C
完全不确认，错了再改
最省事，但金额识别错 → 报销金额错 → 被打回，正好撞上 Q1.2 那个高焦虑场景

本单最见设计判断的一条，展开在文末。

B2 报销单的状态机补问 · 影响最大
A
草稿 → 待审 → 通过 / 退回 → 已打款
5 个状态。覆盖完整链路且包含「钱到没到」—— 这是 Q1.2「查进度」真正关心的终点

最精简。但没了「草稿」不能先存后交，没了「已打款」答不了「钱什么时候到」

5 个状态是最小完整集。owner 排除财务审核那一级 —— 员工看得到却插不上手的节点，放进来只会拉长时间线。

B5 一张发票能不能进多个报销单补问
A
不能，一票一单
已进单的票在票夹里变灰不可勾，hover 提示「已用于 XX 单」
B
能，但给醒目警告
适合拆分报销（一张大额票分摊到两个项目），但会把骨架搞复杂

防重报，且财务合规上本来就不允许重复报销。分摊场景明确划进「后续规划」，不是遗漏。

B4 票夹里已经用掉的票，默认看得见吗补问
A
默认隐藏，可切「显示已用」

B
默认都显示，已用的置灰
一眼看到全部历史。但用一年之后票夹里六成是灰的，真正要用的新票被淡化了

票夹的职责是「待处理的池子」，不是档案柜。

这单最值得单独说的一条设计判断 · Q4.3

把校验挪到「代价真正发生」的那一刻，而不是「数据产生」的那一刻。

传票时人在「清库存」心态 —— 批量、快、不想被打断；
组单时人在「要交出去了」心态 —— 愿意逐项核对。
同样一件事，放对时机就不烦人。
